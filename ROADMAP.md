- 2026-10-15 ✱ **Group into sub-process makes an expanded sub-process round the selection** (content stays where it is, a start event on the left, end events on the right, what sits right of the selection moves right; the pool and holding sub-processes widen first, so nothing leaves its pool). One step reached from outside: start → that step. Several: start → exclusive gateway → each, after the user's yes. Each place reached outside gets an end event of its own inside (the branch keeps its condition and default); several places: an exclusive gateway after the sub-process repeats the choice with the same names and conditions (no merge gateway inside: it would join branches that carry conditions). The user is asked before gateways are added (they may need to be parallel). Message flows stay on the inner steps, data and boundary events come along; the sub-process takes the lane holding most selected steps. **Ungroup** puts the steps back, removes the "none" start and end events only when flows came in or went out, joins each flow in to each step after the start event and each flow out to each step before an end event (a branch keeps its own condition, so two branches may join the same two elements), moves message flows, data and notes on the sub-process to its first or last step; a collapsed sub-process's content is brought to where the sub-process was. It refuses a sub-process with boundary events, or flows in or out without a plain start or end event. The canvas no longer raises a selected shape above the others (a selected expanded sub-process covered its steps).

- 2026-10-15 ✱ **Model check (stage 3)**: `lintModel` in `core/lint.ts`, one pass per process level (a pool's top level, each sub-process, the free canvas; a boundary event sits on its host's level and reachability goes on through it). P02 reports only the cause: a step whose predecessor is already unreachable (or whose successor already has no way to an end) is left out, unless they are on one loop. A loop no flow leaves is P17, not P02 step by step. P07 matches a join with the nearest node with several ways out that every incoming branch comes from (walking back, not past the join); a task with several outgoing flows counts as an AND split (the course allows that implicit split); a parallel join on a loop gets its own message (deadlock). P08 is info only (the course allows an XOR join straight into a task). P09: one word, a first word ending like a noun (-tion, -ment, -al…), an -ing form, a generic verb (do, handle, process, manage, perform), more than 5 words, a small first letter. P15 "pool without lanes" only with `expectLanes` (a case that names roles). Issues are a question, not a verdict: the Check panel is opened by the user, marks on shapes show only while it is open.
